# 2026-10：项目记忆结构与使用体验调整

本计划对应用户确认的“理解需求—讨论—拆解与计划—执行—交付检查—后来反馈”，同时服务接手、核查与学习。实现不会证明市场需求成立，需要真实用户任务验证。

## 已实现并自动验证

- 兼容旧档案的事项 ID、父/关联关系、阶段与发生/补录时间；分类和阶段不触发自动归并。
- 可选内容分组，独立的讨论事件、实际执行、交付检查与反馈；新记录不强迫填写假设与指标。
- 未知项目扩展字段/小节保留；摘要不覆盖原始依据；已知附件包装与协调短句从核心阅读中排除。
- 分层详情、来源展开、同事项关联、明确关键词加粗；桌面与 320–390px 手机检查。
- 完整原文与 SHA-256 档案包、项目接手资料、Claude 记忆文本、LangChain Markdown；支持实际源覆盖。
- 只读同步差异检查、备份更新与项目偏好保留；在三个本地测试项目验证管理文件同步。
- 显式项目列表的本地总览，每 10 秒读取元数据并启动独立项目看板；仅回环地址，未做全盘扫描或开机服务。

## 继续验证与未完成范围

- 历史：已对一个本地项目的回填引文与原始导出逐条核对，仍有未映射消息；其他测试项目本轮只更新规则和看板，没有完成新的全量历史回填。具体来源与覆盖清单留在各项目的私有目录。
- 外部平台：需在 Claude 记忆入口和目标 LangChain 运行环境实际导入，检查遗漏、项目隔离和不确定性。文件格式生成不等于平台接入通过。
- 用户试用：招募非技术独立创作者、跨工具开发者、多人/多 Agent 用户、非代码持续项目用户。分别执行“找起因、核对理解、换会话接手、后来补结果”，比较查找时间、漏记/误记、纠错成本及主动回访。
- 线上公开演示：继续核对 Pages 设置与 Actions。此前浏览器缺少登录且 CLI 未登录，尚无已验证线上部署；不能把本地预览说成公开发布。
- 跨设备：需要选择托管、身份认证和更新方式，当前 localhost 不提供跨设备同步。
- 事项整理：已有档案不会因分类相似自动合并；拆分/合并应先给来源与建议、保留快照及 ID 对应，再按用户授权执行。

## 发布前检查

运行全量测试、真实源浏览器检查、干净安装与升级，核对分发包不含真实档案和项目列表。Skill 的通用验证脚本需要 PyYAML；本机当前缺少该依赖，不能将此脚本标为通过。公开演示保持合成数据，实际平台/用户验证未完成时明确标记。
