# BuildTrace

这个文件是项目记忆的唯一主源。Agent 在这里记录，Viewer 只读展示。

## 项目初心

- 为什么做这个项目: 不让人的出发点、判断、取舍和行动因果埋在 AI 对话与上下文压缩里。
- 面向谁: 用 AI 做产品、但不一定有成熟工程流程的运营、增长、内容、独立开发者和 vibe coding 用户。
- 目前最重要的判断: 先把 Markdown 主源、Agent 工作流和只读 Viewer 做成可信闭环，再考虑云服务和多项目总览。
- 不想做成什么: 不做普通 changelog，不强迫用户填长表，不维护第二份浏览器数据库，不假装能够恢复不可访问的历史。
- 成功大概长什么样: 几周后用户和新 Agent 都能快速知道当时为什么做、依据在哪、后来是否有效。

### 2026-07-18 — v1.15 建立唯一主仓与只读看板

来源可信度: confirmed
依据: 本轮对话；README.md；docs/buildtrace/viewer/
场景: ux-content
结果状态: 待观察
后续回看: 2026-07-25

沟通原文:
- 用户说：「继续吧，另外目前看板很丑，你看看有什么可优化的」；随后确认：「修复吧」。

需求总结:
- 把过去分散的规则和旧看板收进唯一主仓，并把看板重做成可信、好看、能在手机上真正使用的只读项目脉络工具。

为什么做:
- 旧版界面同时展示统计、操作、资源、时间线和详情，主任务不清楚；更严重的是规则要求 Markdown 唯一主源，旧 Viewer 却继续读取 JSON 和浏览器缓存，用户无法相信自己看到的是否是真实项目记录。

做了什么:
- 建立 v1.15 目录、版本、README、Markdown 主记录、只读 Viewer、CLI 和测试。
- Viewer 改为直接解析本文件；手机采用节点列表到全屏详情的两层流程。

技术备注:
- 主要文件：`docs/buildtrace/viewer/index.html`、`app.js`、`parser.js`、`styles.css`、`bin/buildtrace.mjs`。
- 验证：10 项 Node 测试与 doctor 通过；桌面 1440px、平板 820px、手机 390px 浏览器检查通过。
- 浏览器检查覆盖：看板读取 3 条真实记录、教程导航、中英文切换、手机全屏详情、横向溢出和控制台错误。
- 分发检查覆盖：CommonJS 项目安装、既有 AGENTS.md 不覆盖、证据缺失拦截、重复标题唯一 ID 和损坏浏览器设置恢复。

结果:
- 教程与看板双形态已经完成，并修复了手机详情离屏导致的横向溢出和返回图标尺寸问题；目前自动化验收无控制台错误，保留待观察状态，在 2026-07-25 回看真实使用效果。

### 2026-07-17 — 明确 BuildTrace 的产品定位与当前缺口

来源可信度: confirmed
依据: 用户要求从真实用户视角理解项目；历史 v1.14 分发包检查
场景: decision
结果状态: 有效

需求总结:

技术备注:
- 本条来自产品审查结论；旧包只作为迁移证据，不再作为当前主源。

结果:
- 这次审查直接形成 v1.15 的修复范围，判断有效。
