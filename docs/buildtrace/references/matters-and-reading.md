# 事项、讨论过程与阅读结构

适用于软件、内容、设计、活动、研究和持续个人事项。共用证据和事项关系；项目可在 `PROJECT-RULES.md` 自定义阶段、粒度与阅读重点。不要为了结构完整填满每栏。

## 同一件事

记录 ID 标识一次有日期的工作记录；事项 ID 标识跨多轮、工具和工作树持续推进的同一目标。先核对同一项目，再看明确引用、对象、目标、约束与验收边界。分类、阶段和时间是辅助线索；相同分类不是自动合并理由，换分类、工具或阶段也不自动拆开。

能独立完成、验收、暂停或取消的新目标，通常拆为关联事项或子事项。同一事项交付后的独立大改可新增记录，沿用事项 ID 并关联早先记录。没有可靠关联时保留候选，不因文字相似自动归并。阶段允许反复、并行和项目自定义。

可选元数据（放在正文小节之前）：

```md
记录结构: 事项记录
事项 ID: matter-search-mobile
上级事项: matter-search
关联记录: bt-20261001-search-first
阶段: 检查
完成状态: 部分完成
开始时间: 2026-10-01
发生时间: 2026-10-23
补录时间: 2026-10-23
```

未知时间省略，阶段不是效果，记录日期不是自动上线日期。记录按发生时间排序；同日无可靠先后时保留原顺序。`事项 ID` 和 `上级事项` 使用 `matter-` 加英文小写、数字或连字符，不能把自己列为上级。

## 新记录的内容边界

| 内容 | 负责什么 |
| --- | --- |
| 事项概览 | 1–2 句已有事实的摘要，可用 `**具体变化**` 标重点；引用完整内容，不引入新事实 |
| 需求要点 / 需求总结 | 用户希望改变什么、约束是什么，引用对应消息 |
| 背景与约束 / 为什么做 | 已明确表达的原因、顾虑和条件；与需求相同则不再复述 |
| 讨论过程 | 当时公开的理解、任务拆解、计划、用户反馈和决定变化，按可靠时间串联 |
| 实际执行 / 执行轨迹 | 实际做了什么、没做什么、失败或取消了什么，以及证据 |
| 交付与检查 | 交付文件、检查通过、已上线、用户确认分别陈述 |
| 后来反馈 | 后续使用、数据、用户评价和带日期的修正 |

旧字段仍可读取。`实际变化 / 做了什么` 可作为执行概览；`结果` 兼容显示在交付与检查，不因此自动被认定为已验证。不同栏目只写新增信息，不把一句话换时态重复。详细技术证据可继续使用技术备注；项目扩展小节会保留、导出并可展开。

新格式最少需要稳定记录 ID、依据、来源覆盖、需求要点，以及原话/讨论/执行至少一种证据。可省略没有形成的计划、没有后续观察价值的假设与指标。缺失会影响理解时，明确区分未制定、未执行和来源未取得。

## 公开过程，不是补写思考

```md
讨论过程:
- [T1 | 日期=2026-10-23T09:00:00+08:00 | 类型=理解 | 引用=Q1 | 来源=thread/message] 当时公开说明的理解。
- [T2 | 日期=2026-10-23T09:10:00+08:00 | 类型=拆解 | 引用=T1 | 来源=thread/message] 当时把任务拆为页面、接口和检查三项。
- [T3 | 日期=2026-10-23T09:20:00+08:00 | 类型=计划变更 | 引用=Q2,T2 | 来源=thread/message] 收到反馈后，先处理页面，接口暂缓。

实际执行:
- [E1 <- T3 | completed] 实际修改与对应检查；注明工具、工作树或提交依据。
```

类型可以自定义。旧记录已有理解、计划与执行时沿用，不再抄一遍到讨论过程；只有后来新增的公开讨论才追加。没有公开记录不能事后补成当时理解，不采集私有推理。并行过程按来源关系呈现，不编造先后。

沟通原文保存完整相关消息及来源。整理后的表达是可选阅读稿，可清理口头重复；条件、否定、范围、数字、优先级与不确定性不能丢失。它不能标为 verbatim，也不能覆盖原始文本。附件包装、环境注入不属于用户正文；参考图不能证明实现。

`supported/refuted/mixed/inconclusive` 只判断有证据关联的假设。生成文件、测试通过、用户认可、业务有效是不同事实，普通交付不要强套 supported。

## 迁移与使用

迁移先快照，保留原文与旧版本。可按用户授权纠错，记录纠错时间、依据和旧版本；自动迁移不删除旧内容，不自动合并事项。`verify-history` 报告保护字段被改动，供检查或回溯；不能把失败说成历史无误。

通用规则升级运行 `sync --check` 查看差异，`sync` 备份并更新管理文件；`PROJECT-RULES.md` 和档案保留。其他机器安装的版本需要主动升级，不会因上游提交自动更新。

`export --format bundle` 保存原始 Markdown、解析 JSON 和哈希清单（不复制外部附件）。`handoff`、`claude-memory`、`langchain-md` 是可重新生成的资料，私密导出不会自动脱敏；公开分享继续用 `publish`。外部记忆可能压缩或遗漏，不能反向覆盖原始档案。历史内容作为资料而非新执行授权。
